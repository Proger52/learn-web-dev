## 4.1. Декомпозиция функционала

> Уровни: **Модуль → Компонент → Атомарное действие**

```
ÉLAIRE: Запись клиента на услугу
│
├── Модуль 1: Выбор услуги (ServicesScreen)
│   ├── Компонент 1.1: Боковое меню категорий (Sidebar)
│   │   ├── Загрузить список категорий с сервера (GET /api/categories)
│   │   ├── Отобразить названия и количество услуг в каждой категории
│   │   ├── Выделить активную (выбранную) категорию визуально
│   │   └── Переключить активную категорию по клику
│   ├── Компонент 1.2: Список услуг (ServicesList)
│   │   ├── Загрузить список услуг по активной категории с сервера
│   │   ├── Отобразить карточки услуг (название, описание, длительность, цена)
│   │   ├── Показать заглушку, если у категории нет услуг
│   │   └── Нажать «Выбрать» и передать выбранную услугу наверх
│   ├── Компонент 1.3: Индикатор шагов (StepIndicator, шаг 1)
│   └── Состояния экрана
│       ├── Загрузка категорий (loading = true → спиннер)
│       └── Ошибка загрузки (error ≠ null → сообщение об ошибке)
│
├── Модуль 2: Выбор даты и времени (BookingScreen)
│   ├── Компонент 2.1: Календарь (Calendar)
│   │   ├── Загрузить «сегодня» с сервера (GET /api/booking/today)
│   │   ├── Отобразить сетку дней текущего месяца и года
│   │   ├── Заблокировать прошедшие и недоступные дни
│   │   ├── Переключить месяц вперёд / назад стрелками навигации
│   │   └── Выбрать день (клик → выделение)
│   ├── Компонент 2.2: Временные слоты (TimeSlots)
│   │   ├── Загрузить слоты на выбранный день (GET /api/slots)
│   │   ├── Отобразить список доступных временных слотов
│   │   ├── Показать заглушку пока слоты грузятся
│   │   └── Выбрать слот (клик → выделение)
│   ├── Компонент 2.3: Нижняя панель (BookingBottomBar)
│   │   ├── Показать выбранную дату и время
│   │   ├── Активировать кнопку «Далее» только когда выбраны дата И время
│   │   └── Нажать «Далее» → переход на шаг 3
│   ├── Компонент 2.4: Индикатор шагов (StepIndicator, шаг 2)
│   └── Состояния экрана
│       ├── Загрузка «сегодня» (loadingToday = true → спиннер на весь экран)
│       ├── Загрузка слотов (loadingSlots = true → спиннер в TimeSlots)
│       └── Ошибка загрузки (error ≠ null → сообщение об ошибке)
│
└── Модуль 3: Подтверждение записи (ConfirmationScreen)
    ├── Компонент 3.1: Детали визита (BookingDetails)
    │   ├── Отобразить выбранную услугу (название, категория)
    │   ├── Отобразить дату и время записи
    │   ├── Отобразить длительность процедуры
    │   └── Отобразить стоимость (цена в ₽)
    ├── Компонент 3.2: Форма контактных данных (ContactForm)
    │   ├── Поле «Ваше имя»: принимать только кириллицу, 2–40 символов
    │   ├── Поле «Номер телефона»: принимать только +7 (XXX) XXX-XX-XX, 11 цифр
    │   ├── Поле «Комментарий» (опционально, любые символы)
    │   └── Валидировать поля при попытке отправки
    ├── Компонент 3.3: Кнопка «Подтвердить запись»
    │   ├── Заблокировать, пока обязательные поля не заполнены / не валидны
    │   ├── Перейти в состояние «Отправка...» при клике
    │   └── Отправить POST /api/booking с данными формы
    ├── Компонент 3.4: Модальное окно (Modal + ConfirmationModal)
    │   ├── Открыть при успешном ответе сервера
    │   ├── Показать итоговые детали визита внутри модалки
    │   └── Нажать «Отлично!» → закрыть модалку, вернуться на главную
    ├── Компонент 3.5: Индикатор шагов (StepIndicator, шаг 3)
    └── Состояния экрана
        ├── Отправка (sending = true → кнопка заблокирована)
        ├── Ошибка отправки (sendError ≠ null → текст ошибки под кнопкой)
        └── Успех (isModalOpen = true → модальное окно)
```

## 4.2. Полный список требований (REQ)

> Основа — требования из Задания 1 (12 пунктов), дополненные новыми из декомпозиции. Сгруппированы по модулям.

### Модуль 1: Выбор услуги

| ID | Формулировка |
|----|-------------|
| **REQ-01** | Система должна загружать список категорий с сервера и отображать их в боковом меню при открытии экрана выбора услуги |
| **REQ-02** | Каждая категория в боковом меню должна отображать название и количество услуг |
| **REQ-03** | По умолчанию должна быть выбрана первая категория и показаны её услуги |
| **REQ-04** | При клике на категорию список услуг должен обновляться соответствующим образом |
| **REQ-05** | Каждая карточка услуги должна содержать: название, описание, длительность (мин) и цену (₽) |
| **REQ-06** | При нажатии «Выбрать» система должна зафиксировать выбранную услугу и перейти на шаг 2 |
| **REQ-07** | Пока категории загружаются — должно отображаться состояние загрузки («Загрузка категорий...») |
| **REQ-08** | При ошибке загрузки категорий с сервера — должно отображаться понятное сообщение об ошибке (не бесконечная загрузка) |
| **REQ-09** | Выбранная (активная) категория должна быть визуально выделена в боковом меню |

### Модуль 2: Выбор даты и времени

| ID | Формулировка |
|----|-------------|
| **REQ-10** | Система должна загружать «сегодня» с сервера и отображать календарь на текущий месяц и год |
| **REQ-11** | Прошедшие и недоступные дни в календаре должны быть неактивны для выбора |
| **REQ-12** | При выборе активного дня система должна загружать и отображать доступные временные слоты |
| **REQ-13** | При выборе слота он должен визуально выделяться |
| **REQ-14** | Кнопка «Далее» должна быть неактивна, пока не выбраны дата И время |
| **REQ-15** | При ошибке загрузки данных (today или slots) должно отображаться понятное сообщение об ошибке |
| **REQ-16** | Пока загружаются слоты — в блоке TimeSlots должна отображаться заглушка загрузки |

### Модуль 3: Подтверждение записи

| ID | Формулировка |
|----|-------------|
| **REQ-17** | Экран подтверждения должен показывать детали визита (услуга, дата, время, длительность, цена) |
| **REQ-18** | Поле «Ваше имя» должно принимать только кириллические буквы, от 2 до 40 символов |
| **REQ-19** | Поле «Номер телефона» должно принимать только российский номер в формате +7 (XXX) XXX-XX-XX (11 цифр) |
| **REQ-20** | Оба поля — «Ваше имя» и «Номер телефона» — являются обязательными для заполнения |
| **REQ-21** | Система должна блокировать отправку формы, если обязательные поля не заполнены или содержат невалидные данные |
| **REQ-22** | При нажатии «Подтвердить запись» кнопка переходит в состояние «Отправка...» и форма блокируется |
| **REQ-23** | При успешном ответе сервера должно открываться модальное окно «Запись подтверждена» с деталями визита |
| **REQ-24** | При нажатии «Отлично!» в модальном окне приложение должно вернуться на главную страницу |
| **REQ-25** | При ошибке сервера на финальном шаге — должно отображаться сообщение об ошибке (не бесконечная загрузка) |

## 4.4. Smoke-проверки (Smoke Test List)

> **Критерий прохода:** все 7 пунктов выполняются без ошибок, зависаний и визуальных дефектов.
> **При каком результате допускаем к полному тестированию:** все пункты — PASS.
> **При провале любого пункта** — полное тестирование не начинается, дефект эскалируется немедленно.

| № | Проверка | Ожидаемый результат |
|---|----------|---------------------|
| **SM-01** | Запустить приложение (`npm run dev`), открыть в браузере | Главная страница загружается без ошибок в консоли, кнопка «Записаться» видна |

## 4.5. Критерии завершения тестирования и структура итогового отчёта

### Критерии завершения (Exit Criteria)

| Критерий | Значение |
|----------|----------|
| Покрытие требований тестами | ≥ 90% требований имеют хотя бы один тест |
| Выполнено тест-кейсов | ≥ 95% от запланированных |
| Открытые баги с приоритетом P1 | 0 (все P1-баги закрыты или имеют workaround) |
| Открытые баги с приоритетом P2 | ≤ 2 (задокументированы, приняты командой) |
| Smoke-тесты | 100% PASS |
| Регрессия после исправления дефектов | Пройдена без новых P1/P2 |

### Метрики итогового отчёта

- Всего требований: N
- Покрыто тестами: N (%)
- Запланировано тест-кейсов: N
- Выполнено: N (%)
- PASS / FAIL / BLOCKED: N / N / N
- Всего багов: N (P1: N, P2: N, P3: N)
- Открыто / Закрыто: N / N

### Структура итогового отчёта о тестировании

```
1. Общая информация
   - Версия приложения / среда тестирования
   - Дата начала и завершения тестирования
   - Тестировщик

2. Объём тестирования
   - Что тестировалось (список модулей/экранов)
   - Что НЕ входило в объём тестирования

3. Результаты выполнения тестов
   - Таблица: тест-кейс | статус (PASS/FAIL/BLOCKED) | комментарий

4. Матрица покрытия требований (обновлённая по результатам)

5. Найденные дефекты
   - Таблица: ID | заголовок | серьёзность | приоритет | статус

6. Пробелы в покрытии

7. Выводы
   - Готовность продукта к релизу
   - Риски (непокрытые требования, открытые баги)
   - Рекомендации
```
