## Задание 2.2. Баг-репорт

### BUG-001: Поле «Номер телефона» принимает буквы и спецсимволы — маска +7 не валидирует ввод

| Поле | Значение |
|------|----------|
| **ID** | BUG-001 |
| **Заголовок** | Поле «Номер телефона» на шаге «Подтверждение записи» не валидирует ввод: принимает буквы, спецсимволы и произвольный формат номера вместо маски +7 |
| **Серьёзность** | Major |
| **Приоритет** | High |
| **Окружение** | Web-приложение ÉLAIRE; браузер: Google Chrome 130+ / Firefox 131+; ОС: Windows 11; разрешение: 1920×1080 |
| **Статус** | Открыт (Open) |

#### Шаги воспроизведения

1. Открыть приложение и нажать кнопку «Записаться» на главной странице.
2. На шаге 1 выбрать любую категорию и нажать «Выбрать» на любой услуге.
3. На шаге 2 выбрать доступный день в календаре, затем любой временной слот. Нажать «Далее».
4. На шаге 3 «Подтверждение записи» заполнить поле «Ваше имя» (например, «Анна Петрова»).
5. В поле «Номер телефона» ввести строку с буквами и спецсимволами (например, `аbcde!@#`).
6. Нажать кнопку «Подтвердить запись».

#### Ожидаемый результат

Поле «Номер телефона» должно:
- Принимать только цифры в формате маски `+7 (XXX) XXX-XX-XX`.
- Показывать ошибку валидации при вводе недопустимых символов (букв, спецсимволов).
- Блокировать отправку формы при некорректном номере.

#### Фактический результат

Поле принимает любые символы — буквы, спецсимволы, произвольное количество символов. Маска `+7` не выполняет проверку формата при отправке. Запись успешно «подтверждается» с заведомо некорректным номером телефона (например, `аbcde!@#`).

#### Дополнительные данные

| Поле | Описание |
|------|----------|
| **Скриншот** | На скриншоте: шаг 3, экран «Подтверждение записи». Поле «Номер телефона» содержит значение `+7 (999) 123-45-67` — но ввод аналогичного вида строки с буквами/спецсимволами также проходит без ошибки. Поле визуально выглядит корректно (рамка не краснеет), кнопка «Подтвердить запись» активна. |
| **Данные окружения** | Тестировалось в браузере Chrome 130 на Windows 11 (1920×1080), а также Firefox 131. Дефект воспроизводится в обоих браузерах. Backend: dev-сервер Vite (`npm run dev`). |
| **Компонент** | `src/screens/ConfirmationScreen.jsx` → `<ContactForm />` → поле `phone` |

#### Обоснование серьёзности и приоритета

- **Серьёзность — Major**: Дефект затрагивает бизнес-логику приложения. Запись клиента с некорректным номером означает, что сотрудник салона не сможет связаться с клиентом для подтверждения визита. Это напрямую влияет на работу бизнеса.
- **Приоритет — High**: Дефект воспроизводится на финальном шаге ключевого пользовательского сценария при любом ручном вводе. Не требует специальных условий. Должен быть исправлен в ближайшем релизе.

## Задание 2.3. Use Case

### UC-01: Запись клиента на услугу в онлайн-приложении ÉLAIRE

| Поле | Значение |
|------|----------|
| **ID** | UC-01 |
| **Название** | Запись клиента на услугу |
| **Актор** | Клиент (пользователь веб-приложения) |
| **Предусловие** | Клиент открыл веб-приложение ÉLAIRE; сервер доступен и возвращает данные |
| **Постусловие (успех)** | Запись зарегистрирована в системе. Клиент видит подтверждение со всеми деталями визита |
| **Постусловие (неуспех)** | Запись не создана. Система сообщает об ошибке |

#### Основной поток (Basic Flow)

1. Клиент открывает главную страницу и нажимает кнопку «Записаться».
2. Система отображает экран «Выбор услуги» с боковым меню категорий. По умолчанию загружается первая категория.
3. Клиент выбирает нужную категорию в боковом меню.
4. Система загружает и показывает список услуг выбранной категории.
5. Клиент нажимает «Выбрать» на карточке подходящей услуги.
6. Система фиксирует выбор и переходит на экран «Выбор даты и времени».
7. Система загружает текущую дату с сервера и отображает календарь.
8. Клиент выбирает нужный день в календаре.
9. Система загружает и отображает доступные временные слоты на этот день.
10. Клиент выбирает удобный слот времени.
11. Клиент нажимает кнопку «Далее».
12. Система переходит на экран «Подтверждение записи» и показывает детали визита (услуга, дата, время, мастер, длительность, цена).
13. Клиент вводит имя и номер телефона (опционально — комментарий).
14. Клиент нажимает «Подтвердить запись».
15. Система отправляет данные на сервер (POST /api/booking).
16. Сервер успешно создаёт запись и возвращает код 200.
17. Система открывает модальное окно «Запись подтверждена» с итоговыми деталями визита.
18. Клиент нажимает «Отлично!» — приложение возвращается на главную страницу.

#### Расширение A: Выбор категории (точка разветвления на шаге 3)

- **A1** — Клиент хочет найти услугу, но не уверен в категории:
  - A1.1. Клиент поочерёдно кликает по разным категориям в меню.
  - A1.2. Система каждый раз подгружает список услуг выбранной категории.
  - A1.3. Клиент останавливается на нужной категории и выбирает услугу → возврат к шагу 5 основного потока.

#### Расширение B: Негативный сценарий — ошибка сервера при загрузке категорий (шаг 2)

- B1. Сервер недоступен или вернул ошибку.
- B2. Система отображает сообщение об ошибке (например, «Не удалось загрузить категории. Попробуйте позже»).
- B3. Кнопка «Выбрать» не активна. Клиент не может продолжить запись.

#### Расширение C: Негативный сценарий — пустое поле «Номер телефона» (шаг 14)

- C1. Клиент не заполнил поле «Номер телефона» и нажал «Подтвердить запись».
- C2. Система блокирует отправку формы и выделяет незаполненное поле как обязательное.
- C3. Клиент заполняет поле корректным номером → возврат к шагу 14 основного потока.
